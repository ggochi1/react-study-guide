git 설치

코드의 변경 기록을 저장하는 도구. 게임의 세이브 포인트와 같습니다.

  • 실수해도 이전 상태로 복구 가능

  • 설치 순서는 노션 0번 캡처 화면 그대로 따라 하기
시험 포인트 · 이 페이지는 글이 아니라 이미지라서 요약이 짧습니다. 설치 캡처를 한 번 더 보세요.
01

HTML · 웹페이지의 뼈대

내용과 구조를 만드는 언어. 집으로 치면 기둥과 벽.

  • 태그: <p>내용</p> = 시작 + 내용 + 종료 → 요소
  • 종료 태그 없음: img input br hr
  • 제목 h1~h6, 문단 p, 목록 ul/ol/li
  • 링크 a href, 이미지 img src alt
  • 블록(div, p)은 새 줄 / 인라인(span, a)은 글 속
  • 시맨틱: header nav main section article aside footer
<a href="https://github.com/">GitHub</a>
<img src="profile.png" alt="프로필 사진" />
시험 포인트 · alt는 이미지 대체 글. title은 브라우저 탭 제목, body는 화면 내용. 라디오는 하나만, 체크박스는 여러 개 선택.
02

CSS · 꾸미기

모양과 배치를 정합니다. 문법은 선택자 { 속성: 값; }

  • 연결: <link rel="stylesheet" href="style.css">
  • 선택자: 태그 p · 클래스 .intro · ID #title
  • color 글자색, background-color 배경색, font-size 크기
  • margin: 24px auto → 가로 가운데 정렬
  • display: block / inline / inline-block / none
  • :hover = 마우스를 올렸을 때
시험 포인트 · 안쪽 여백은 padding, 바깥 여백은 margin. 같은 요소에 규칙이 겹치면 뒤에 쓴 규칙이 이깁니다(우선순위 같을 때). 개발자 도구는 F12.
03

JavaScript · 동작 넣기

버튼을 누르면 글자가 바뀌는 것처럼, 사용자 행동에 반응합니다.

  • const 다시 대입 안 함 · let 다시 대입함 · var 안 씀
  • 배열 번호는 0부터 시작: arr[0]
  • 객체: person.name으로 접근
  • 백틱 템플릿: `${이름}님`
  • === 값과 자료형까지 같은가
  • 11 % 5 = 1 (나머지)
버튼 클릭→함수 실행→textContent 변경
const btn = document.querySelector("#b");
btn.addEventListener("click", changeIntro);
// changeIntro  ← 이름만 (OK)
// changeIntro() ← 바로 실행 (X)
시험 포인트 · 일반 JS는 변수를 바꿔도 화면이 자동으로 안 바뀜 → textContent도 바꿔야 함. 요소를 못 찾으면 null.
04

React 시작 · 컴포넌트와 JSX

React는 화면(UI)을 만드는 JavaScript 라이브러리입니다. 새 언어가 아닙니다.

  • Node.js 실행 환경 · npm 설치 도구 · Vite 개발 서버
  • 실행: npm run dev → localhost:5173 · 종료 Ctrl+C
  • 컴포넌트 = 화면의 부품, 이름은 대문자로 시작
  • src/App.jsx 주요 화면 · main.jsx 시작 코드
HTMLJSX
classclassName
<img><img /> 닫기
여러 요소하나로 묶기 / <></>
<!-- -->{/* */}
const name = "한코딩";
return (
  <h1>안녕, {name}!</h1>
);

{ } 안에 JS 값을 넣습니다. {name}은 값, name은 글자 그대로.

시험 포인트 · 속성에도 { }: src={profile.imageUrl}. 따옴표로 쓰면 글자 그대로 들어갑니다.
05

컴포넌트와 props

부품(컴포넌트)을 한 번 만들고, props로 내용만 바꿔 여러 번 씁니다.

// 부모
<ProfileCard name="한코딩" />
// 자식 (구조 분해로 받기)
function ProfileCard({ name }) {
  return <h2>{name}</h2>;
}
  • 다른 파일로 쓰려면 export default 후 import
  • props는 읽기 전용: 자식이 props.name = ...으로 바꾸면 안 됨
  • 기본값: { name, intro = "준비 중" } → 값이 없을 때(undefined)만 사용
시험 포인트 · 문자열은 "3", 숫자는 {3}. 컴포넌트는 App 바깥에 정의.
06

목록과 조건부 렌더링

데이터를 배열에 모아 두고 map으로 카드를 찍어냅니다.

배열 [ ■ ■ ■ ]→ map() →카드 ▢ ▢ ▢
{profiles.map((p) => (
  <ProfileCard
    key={p.id}
    name={p.name}
  />
))}
도구하는 일
map바꿔서 새 배열
filter조건에 맞는 것만 새 배열
조건 && A참일 때만 A 표시
조건 ? A : B둘 중 하나 표시
시험 포인트 · key는 목록 안에서 고유한 id (Math.random() 금지). {length && ...}는 0이 화면에 나올 수 있어서 length > 0 &&로 씁니다.
07

이벤트와 state

state = 화면과 연결된 값. 바뀌면 React가 화면을 다시 그립니다.

클릭→핸들러 실행→setState 요청→다시 렌더링→화면 반영
const [count, setCount] = useState(0);
//     현재값   변경 함수       초기값

setCount(prev => prev + 1); // 이전 값 기준
propsstate
누가 줌부모가 전달내가 관리
변경자식이 못 바꿈set 함수로 변경
예이름, 소개횟수, 펼침 여부
  • onClick={handle} (O) / onClick={handle()} (X, 바로 실행됨)
  • count = count + 1 직접 대입 금지 → setCount 사용
  • useState는 컴포넌트 최상위에서만 호출
시험 포인트 · setCount(count+1)을 3번 쓰면 +1만, 함수형(prev => prev+1) 3번이면 +3. 같은 컴포넌트를 두 번 써도 state는 각자 따로.
08

입력 폼과 할 일(Todo) 앱

핵심 규칙 한 줄: 배열과 객체는 직접 바꾸지 않고, 새로 만들어서 set 한다.

기능코드
입력창 연결value={title} + onChange={e => setTitle(e.target.value)}
제출onSubmit 안에서 e.preventDefault() (새로고침 방지)
빈 입력 막기title.trim() === ""이면 return
추가setTasks(prev => [...prev, newTask])
삭제prev.filter(t => t.id !== id)
완료 토글prev.map(t => t.id===id ? {...t, completed: !t.completed} : t)
남은 개수tasks.filter(t => !t.completed).length (계산해서 사용)

틀림 tasks.push(newTask)
맞음 [...tasks, newTask]

틀림 task.completed = true
맞음 {...task, completed: true}

시험 포인트 · 체크박스는 checked, 텍스트는 value. label 연결은 htmlFor. 새로고침하면 데이터가 사라지는 이유는 state가 화면 안에만 있기 때문.
